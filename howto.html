How to work an issue

Back to the schedule

This is the whole loop we'll use for the rest of the semester: pick an issue, make a branch, change something, open a pull request, review it together in class. The site is small and unfinished on purpose, so there is plenty to fix.

Repo: github.com/mattkirkland/ixd415-hearmeout
Live site: mattkirkland.github.io/ixd415-hearmeout

Before you start you need a GitHub account, git installed, your terminal (Git Bash on Windows, Terminal on Mac), and a code editor. If you set these up earlier in the course you're ready. Commands below go in the terminal, one line at a time.

Step 1. Get the repo onto your computer

You only do this once. Clone makes a full copy of the repo, history included, in a folder on your machine. 

cd ~/Sites
git clone https://github.com/mattkirkland/ixd415-hearmeout.git
cd ixd415-hearmeout

Use whatever folder you keep projects in instead of ~/Sites. If git asks you to sign in, use your GitHub username and a personal access token, or sign in through GitHub Desktop if you'd rather.

Check that it worked: ls should show index.html, style.css, script.js, and README.md. Open index.html in a browser. That's the site.

If you've already cloned it before, skip the clone and just make sure you're up to date:

git checkout main
git pull

Step 2. Pick an issue and claim it

Go to the Issues tab.

Each issue is one small, self-contained change. Labels say what kind of work it is (html, css, js, content, a11y). The ones marked good first issue are the smallest; start there if this is your first time through the loop.

Open the issue you want and leave a comment: "I'll take this one." That's how everyone else knows not to pick it. If someone already claimed it, pick another.

Note the issue number. You'll use it in your branch name and your commit message, which is how GitHub connects your work back to the issue.

Step 3. Make a branch

A branch is a separate line of work. You make your change there, not on main, so the live site stays intact until we've reviewed it.

Start from an up-to-date main, then make a branch named for your issue:

git checkout main
git pull
git checkout -b issue-16-dark-mode

Name it issue-<number>-<a-few-words>. Lowercase, hyphens, no spaces. git checkout -b creates the branch and switches you to it in one step.

To see where you are at any time: git branch. The one with the asterisk is the branch you're on.

Step 4. Make the change and check it

Open the project folder in your editor and do what the issue asks. Most issues touch one file; the issue says which.

Check your work by opening index.html in a browser and reloading. There's no build step, so what you see is what will go live.

Stay inside the issue. If you notice something else that's broken, leave it and open a new issue for it. One issue, one branch, one pull request keeps reviews short.

git status shows which files you've changed. git diff shows exactly what changed, line by line. Both are worth running before you commit.

Step 5. Commit and push

A commit is a saved snapshot with a message. Push sends your branch up to GitHub.

git add .
git commit -m "Add dark mode (closes #16)"
git push -u origin issue-16-dark-mode

Write the message as a short sentence saying what you did. Include closes #16 (your issue number) and GitHub will close the issue automatically when the PR is merged.

The -u origin <branch> part is only needed the first time you push a new branch. After that, git push on its own works.

If git stops and asks for your name and email, set them once and try the commit again:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Step 6. Open a pull request

A pull request (PR) is a request to merge your branch into main, with a place to talk about it first.

After you push, go to the repo on GitHub. There's usually a yellow banner offering to open a PR for the branch you just pushed. Click Compare & pull request. If the banner isn't there, go to the Pull requests tab and click New pull request, then pick your branch.

Fill in:

  • Title. What you did, in a few words. Your commit message is usually fine.
  • Description. Which issue this closes (Closes #16), what you changed, and anything the reviewer should look at or try. If it's a visual change, paste a screenshot.

Make sure the base is main and the compare is your branch, then click Create pull request.

You can keep working after this. Any new commits you push to the same branch show up in the PR automatically.

Step 7. Review together, merge, see it live

We'll go through open PRs in class. The reviewer reads the diff (the Files changed tab), leaves comments on specific lines if there's something to discuss, and either approves or asks for changes.

If changes are requested, make them on the same branch, commit, and push. The PR updates itself. You don't open a new one.

When it's approved, click Merge pull request, then Confirm merge. Your change is now on main. GitHub Pages rebuilds the live site within a minute or two; reload the live site to see it.

After the merge, get back on main and pull so your copy matches:

git checkout main
git pull

Then pick the next issue and start again from Step 2.

Adding a poster

The second project on this site is a set of posters for the series, one per student, each a different design built on the same shared data. Same loop as above, with a few specifics:

  1. Copy posters/starter to posters/<your-slug>. Lowercase, hyphens, no spaces.
  2. Make the copy yours. Change the HTML and CSS however you like, but keep the speakers, dates, and titles coming from data.js. The top of posters/poster.js explains the attributes that do that.
  3. Add one line for your poster at the end of the list in posters/manifest.js.
  4. Open poster.html in a browser and page to yours to check it.
  5. Branch, commit, push, PR, with a screenshot in the description.

More detail in posters/README.md.

If something goes wrong

I made changes on main by mistake. As long as you haven't committed, you can move them to a new branch: git checkout -b issue-16-dark-mode carries your uncommitted changes with you. Then continue from Step 5.

Push was rejected. Usually you forgot -u origin <branch> the first time, or you're on main. Run git branch to check, then push again with the full command from Step 5.

My PR says it has conflicts. Someone merged a change to the same lines before you. Ask in class; we'll resolve it together. It's a normal thing to run into and worth seeing once.

I want to throw my change away and start over. git checkout main, then git branch -D issue-16-dark-mode deletes the branch. Your clone is a copy; nothing you do locally can break the repo on GitHub.

I don't know what state I'm in. git status is always safe to run and usually tells you what to do next. If it doesn't make sense, ask. Nobody is expected to know git by heart.
